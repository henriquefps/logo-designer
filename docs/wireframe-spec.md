# Wireframe spec (`designer wf build` / `wf dump`)

A compact JSON that describes wireframe screens the way a person thinks of them: logical screens, a tree of
library components and stacks, shared components, flows and notes. No coordinates unless you want them.
Agents write it and read it; `designer wf build` turns it into a project through the same pipeline the app
runs (components, stacks, shared components, repeat, layout), and `designer wf dump` turns any wireframe
project back into one, including what Henrique edited by hand.

Contract: [`wireframe-mode.md`](wireframe-mode.md) → Phase 3 → A1, A2. Code: `src/wireframe/spec/`. JSON Schema:
[`public/schema/wireframe-spec.schema.json`](../public/schema/wireframe-spec.schema.json)
(`https://designer.hfps.dev/schema/wireframe-spec.schema.json`, generated by `bun run schema` from the component
registry, so editors complete every kind and prop). The catalog of components: `designer wf components`.

```sh
designer wf components                      # every component: props, defaults, options, an example (--json too)
designer wf build hoard.spec.json -o hoard.designer.json
designer wf dump hoard.designer.json -o hoard.spec.json
designer wf build hoard.spec.json --into hoard.designer.json   # update in place, by id
```

## Top level

| Key | What |
| --- | --- |
| `screens` | **Required.** Logical screens, in order (below). |
| `components` | Shared components (masters): `{ "name", "id"?, "content" }`, used with `{ "use": "<name>" }`. |
| `flows` | Arrows: `{ "from", "to", "label"?, "id"? }`. Tapping `from` (a node) opens screen `to`. |
| `notes` | Stickies: `{ "text", "on"?, "x"?, "y"?, "id"? }`, `on` = the node it is attached to. |
| `canvas` | Top-level objects that are not in a screen (rare). |
| `name` | Project name (default "Wireframe"). |
| `version`, `$schema` | `1` and the schema URL (optional). |

## Screens

A logical screen has one frame per platform (`phone` 390, `tablet` 820, `desktop` 1440 wide; the height grows
with the content). One frame, the short form:

```json
{ "name": "Settings", "status": "changed", "platform": "phone", "root": [ … ] }
```

Several platforms:

```json
{ "name": "Settings", "variants": [ { "platform": "phone", "root": [ … ] }, { "platform": "tablet", "root": [ … ] } ] }
```

| Key | Default | What |
| --- | --- | --- |
| `name` | (required) | Unique (case-insensitive); flows point at it. |
| `status` | not stated | `current`, `changed` or `new`. |
| `platform` | `phone` | Short form only; variants always say it. |
| `root` | `[]` | The frame's content, in stack order (nodes, below). |
| `layout` | vertical stack, phone padding 16 / gap 12, tablet 24 / 16, desktop 32 / 24, align start | `{ "kind", "gap", "padding", "align", "columns" }` to change it, or `"free"` for no stack (children placed by `x` / `y`). |
| `x`, `y` | right of everything (a variant: next to its screen's other frame) | The frame's top-left on the canvas. |
| `width` | the platform's | An odd width. |
| `id`, `frameId` (variant: `id`) | generated | The logical screen's id and the frame's node id; `dump` writes them. |

## Nodes

Every node is **one** of these, plus the common keys:

| Form | Example |
| --- | --- |
| Library component | `{ "list-row": { "title": "Language", "trailing": "value", "value": "English" } }` |
| … text short form (sets the first text prop) | `{ "heading": "Settings" }`, `{ "button": "Save" }`, `{ "section-header": "GENERAL" }` |
| … list short form (sets the list prop) | `{ "tabs": ["Photos", "Albums"] }` |
| … all defaults | `{ "divider": {} }` or `{ "divider": null }` |
| … explicit | `{ "kind": "list-row", "props": { "title": "Language" } }` |
| Container | `{ "vstack": [ …children ], "gap": 8 }`, `{ "hstack": [ … ] }`, `{ "grid": [ … ], "columns": 3 }` |
| Shared component instance | `{ "use": "Trip card" }` (a name from `components`, or its id) |
| Plain group | `{ "group": [ …children ] }` (children placed by `x` / `y`) |
| Anything else, as in a project file | `{ "node": { "type": "rect", … } }` (what `dump` writes for shapes that are not wireframe pieces) |

Props left out take their default; `designer wf components` lists every kind with its props, types, defaults,
options, when a prop applies (`visibleWhen`) and an example. Plain text is the Text component:
`{ "text": "Some words" }`. Icon props take `"heart"`, `"lucide:Heart"` or `"ph:heart"`.

### Common keys

| Key | What |
| --- | --- |
| `id` | Stable id. `dump` writes one for every node; give your own (`"row-language"`) to refer to it. Unique in the spec. |
| `name` | Layer name (default: the component's label, "Vertical stack", the shared component's name…). |
| `width`, `height` | Size in the stack: `"fill"`, `"hug"` or px. Default: the component's sizing (rows fill, buttons hug); containers fill × hug. `height` only for components that can be taller (cards, images, sheets…: see `Resizable` in the catalog). |
| `position` | `"flow"` (default), `"pinned-bottom"` (direct children of a screen: bottom bars, at the bottom of the screen, full width) or `"free"` (absolute: `x` / `y`). |
| `bleed` | Edge to edge: ignore the stack's side padding (default from the component: rows, bars and headers bleed). |
| `x`, `y`, `size`, `rotation`, `scale` | Only for nodes no layout places (free, in a free screen, in a group, on the canvas): position in the parent, box `{ "width", "height" }`. |
| `hidden`, `locked`, `opacity` | As in the app. |
| `opens` | Sugar for flows: `"opens": "Language"` (or a list) adds a flow from this node. |
| `note` | Sugar for notes: `"note": "Pull to refresh"` attaches a note to this node. |

**Default placement.** A screen child the spec says nothing about takes its component's default position, like an
insert from the library: `bottom-navigation` is pinned to the bottom, a `fab` floats bottom right, a `snackbar` at
the bottom, a `dialog` centred. `"position": "flow"` keeps one in the stack; `"position": "free"` without `x` /
`y` centres it.

### Containers

`vstack` (column), `hstack` (row), `grid`, with these keys next to the children:

| Key | Default (vstack / hstack / grid) | What |
| --- | --- | --- |
| `gap` | 12 / 8 / 12 | Space between children (and between repeated items). |
| `padding` | 0 | Inner padding, every side. |
| `align` | stretch / center / stretch | Cross axis: `start`, `center`, `end`, `stretch`. |
| `columns` | — / — / 2 | Grids only. |
| `style` | `none` | `outline`, `filled`, `outline-filled`: a lo-fi card look. |
| `radius` | `none` | `small` (8), `large` (16): corners of a styled container. |
| `repeat` | off | Repeat the **first child** N times (1–50): a list (vstack), a carousel (hstack), a gallery (grid). |

A card container is `{ "vstack": [ … ], "style": "outline", "radius": "small", "padding": 16, "gap": 8 }`.

### Shared components

```json
"components": [ { "name": "Trip card", "content": { "vstack": [ { "image": {} }, { "heading": "Lisbon" } ], "style": "outline" } } ]
```

`content` is a container or a group; its `width` / `height` / `position` / `bleed` are what a new instance starts
with (a tab bar whose content says `"position": "pinned-bottom"` is pinned on every screen that uses it). Use it
with `{ "use": "Trip card" }`, also as a repeat template or inside another component (never inside itself). Ids
inside `content` are the master's own; an instance's nodes get `<instance id>~s~<master id>`, so a flow can start
inside one instance: `"from": "Home/card/Lisbon"` or `"from": "card~s~title"`.

## Flows, notes and paths

`from` (flows) and `on` (notes) take a node id or a **path**: the screen's name, then node names, labels or ids,
separated by `/`. Each segment matches the first node, depth first, whose id, name or label (title / label / text /
message prop, or a text's content) equals it, case-insensitive: `"Settings/Language"`, `"Settings/Account/Language"`
(inside the stack named Account), `"Settings@tablet/Language"` (the tablet frame; default: the first variant). An
ambiguous segment uses the first match and prints a warning: give the node an `id` to be exact. `to` is a screen
name or id. A path that matches nothing is an error that says which segment failed.

## Ids, dump and `build --into` (round trip)

- `dump` writes every stated node with its id (not the children a component generates, not repeat copies, not an
  instance's content: those come back from the props, the template and the master), leaves defaults out (props,
  layout values, names) and writes the geometry nobody computes: frame positions, free nodes' `x` / `y` / `size`,
  fixed sizes, note positions. `build(dump(p))` is `p` (tested for every container kind, repeat, shared components,
  flows, notes, status, pinned / free placement and multi-variant screens).
- `build --into project` updates that project **by id** (an id-less node updates the node at the same place in the
  same parent when it is the same kind). What the spec states wins: props, structure, order, names, layout,
  status. The **geometry the spec leaves out is kept**: x / y / width / height / size of nodes, frame positions and
  widths, note positions. Only what the spec no longer lists is removed (a flow from a removed node goes, a note on
  it stays, detached, both with a warning). Top-level `components`, `notes`, `flows` or `canvas` left out entirely
  are kept as they are; an empty list removes them.
- `dump --no-geometry` writes no positions or sizes at all: edit that and `build --into`, and every move or resize
  Henrique made in the app meanwhile survives. Canvas order (which frame is on top) is not in the spec.

## Errors

The whole spec is checked before anything is built, and every problem comes back at once with its spec path:

```
$ designer wf build bad.json
Error: the spec has 3 problems:
  screens[1].root[1]: needs one of: a component kind (e.g. "list-row"), "vstack", "hstack", "grid", "use", "group" or "node"
  screens[1].root[2]: needs one of: a component kind (e.g. "list-row"), "vstack", "hstack", "grid", "use", "group" or "node"
  screens[1].root[3].list-row.trailing: "arrow" is not one of none, chevron, toggle, value, checkbox
```

Unknown kinds, props and keys get a "did you mean"; out-of-range numbers, duplicate ids and screen names, a
second frame of the same platform, unknown shared components and paths that match nothing are all errors.

## A complete example

Hoard's Settings screen (top bar, section headers, list rows with values and toggles, a radio group, a button, a
shared tab bar pinned to the bottom) and a Server screen it opens, with a flow back and two notes:

```json

  "version": 1,
  "name": "Hoard",
  "components": [
    {
      "name": "Tab bar",
      "content": {
        "vstack": [{ "bottom-navigation": { "labels": ["Gallery", "Albums", "Settings"], "selected": 3 } }],
        "position": "pinned-bottom"
      }
    }
  ],
  "screens": [
    {
      "name": "Settings",
      "status": "changed",
      "platform": "phone",
      "root": [
        { "top-app-bar": { "title": "Settings", "leading": "none", "actions": 0 } },
        { "section-header": "SERVER" },
        { "list-row": { "title": "Server address", "subtitle": "hoard.hfps.dev", "trailing": "chevron" }, "id": "row-server", "opens": "Server" },
        { "list-row": { "title": "Status", "trailing": "value", "value": "Connected" } },
        { "section-header": "BACKUP" },
        { "list-row": { "title": "Back up automatically", "trailing": "toggle", "checked": true } },
        { "list-row": { "title": "Only on Wi-Fi", "subtitle": "Saves mobile data", "trailing": "toggle", "checked": false }, "note": "Hidden when automatic backup is off" },
        { "radio-group": { "label": "Upload quality", "options": ["Original", "High (2048 px)", "Data saver"], "selected": 1 } },
        { "section-header": "ACCOUNT" },
        { "list-row": { "title": "Language", "trailing": "value", "value": "English" } },
        { "button": { "label": "Sign out", "variant": "secondary" } },
        { "use": "Tab bar" }
      ]
    },
    {
      "name": "Server",
      "status": "new",
      "root": [
        { "top-app-bar": { "title": "Server", "leading": "back", "actions": 0 } },
        { "text-field": { "label": "Address", "placeholder": "https://…" } },
        { "text-field": { "label": "API key", "placeholder": "Paste the key" } },

```

`designer wf build` gives two phone frames side by side, the rows stacked and laid out, the tab bar pinned to the
bottom of both, an arrow from "Server address" to Server and from Connect back to Settings, and the notes next to
the Status and Wi-Fi rows. This file is also the test fixture `src/wireframe/spec/__tests__/hoard-settings.spec.json`
(a test checks the two match).

## For agents: the loop

1. `designer wf components` (once) to know the pieces.
2. Write the spec: library components first, stacks for structure, `use` for anything repeated across screens,
   `repeat` for lists, `opens` / `note` where they belong.
3. `designer wf build spec.json -o app.designer.json`; fix what the errors name; render with
   `designer to-png app.designer.json` and look.
4. To change it later, `designer wf dump app.designer.json --no-geometry -o spec.json`, edit, and
   `designer wf build spec.json --into app.designer.json`: Henrique's edits in between are kept.
